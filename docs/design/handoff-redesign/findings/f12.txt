 The app never invents data: when something can't load, it says so. That rule is right and should stay. The issue is how those messages are worded. Many read like an explanation of the code for whoever reviews the pull request, and the same careful reasoning that sits in the code comments has ended up on screen.
 Jargon on its own is fine for engineers supervising agents. What's missing is that most of these messages don't answer the three questions someone has when something goes wrong: what happened , is my work safe , and what should I do now . Below, four real strings are scored against those questions, with the internal words highlighted.

 A short rulebook for on-screen text
 Answer the three questions: what happened, is my work safe, what to do next.
 No API, component, ADR or status-code names in visible text. Repo, branch and step names are fine, because users chose them.
 Name the person and the time when the data has them.
 End every error with an action: a link, a button, or who to ask.
 The why goes in code comments, which already cover it in detail.
