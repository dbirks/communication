# M3 exit proof — end-to-end script

`e2e_m3_exit.py` is the executable form of the M3 exit criterion in
`docs/m3-contract.md` § 6–§ 7: it runs the real stack, real Postgres, real
Claude Code turns under nono `required` enforcement, and prints the literal
command output for every PASS/FAIL/GAP (the `12-test-strategy.md` reporting
rule). Nothing here is mocked.

## Prerequisites

* Stack up, built from the commit being certified:

  ```bash
  HOST_UID=$(id -u) HOST_GID=$(id -g) \
    docker compose -p communication -f compose.yml -f compose.harness.yml up -d --build
  ```

  (`compose.harness.yml` binds this developer's own real agent logins —
  `~/.claude`, `~/.codex` — and runs the worker as the host uid; it is a lab
  overlay, never committed-with-credentials, and the script refuses to start
  if `http://localhost:18080` readiness is not green.)
* Fixtures present under `.harness/remotes/` (`projA-src.git`, `projB-src.git`,
  `batt-src.git`, `apm-app.git`) — regenerated by the harness lab setup.
* Agent auth valid for the pinned Claude profile (an expired login shows up
  as failed turns, not as a fake pass).
* Host tools: `docker`, `git`, CPython 3 (stdlib only). No new dependencies.

## Run

```bash
python3 e2e/m3/e2e_m3_exit.py 2>&1 | tee run.log
```

Exit code 0 ⇔ zero FAIL lines. GAPs print with their reason and are copied
into the acceptance report verbatim. Scratch state (throwaway worker dirs)
lives under `~/.cache/communication-lab/m3-exit/` (`M3X_SCRATCH` overrides).

## What the X section guarantees (and why it looks like this)

* **ENOENT is not a denial.** An earlier run accepted "permission *or*
  no-such-file" wording while A's probe actually printed `No such file or
  directory` — B's `.env` only exists during B's own turn, so that outcome is
  identical to a world with no sandbox. The rule now: every probe targets a
  path **host-verified present at the instant of the probe**, and only
  `Permission denied` (EACCES) naming the exact target passes — for reads
  *and* writes. Targets:
  1. `…/repos/<B>/backend-b.git/HEAD` — persistent mirror object (read + touch);
  2. `…/workspaces/conversation/<B-conv>/work/repos/backend-b/.env.test.local`
     — while a deliberately long B turn holds it, watched once a second from
     the host (`StatWatch`); the co-existence record prints wall-clock
     windows plus journal `global_seq`/`occurred_at` interleaving
     (B.turn.started < A's probe tool < B.turn.completed), and the probe runs
     on a throwaway *second required worker* so the main worker can be proven
     to still hold B's turn at that moment.
* **X5 negative control.** A throwaway worker container configured
  `COMMUNICATION_SANDBOX_ENFORCEMENT=permissive-dev` (its own name, scratch
  dirs and artifact root; removed afterwards; the main stack's worker keeps
  `required` and is never restarted or reconfigured) runs the *same* paths
  and **must read the file** — readability is proven with a content-extracted
  `md5sum < path` equal to the host-computed md5 (plus a plain `cat` of B's
  mirror `HEAD`), so *no arm, not even the deliberately insecure one, ever
  prints secret bytes*; afterwards the script asserts SENTINEL-B sits in
  zero journal rows globally. Same paths, same uid, same image: the only
  variable is the sandbox. This closes contract § 6 X5 as the negative
  control it is; note the contract's parenthetical "Landlock still applied"
  does **not** match the implementation — `internal/worker/unit.go`
  `Unit.Verify` hands `permissive-dev`/`disabled` units a plain, fully
  unsandboxed plan, and the labelling is what makes the mode honest (the
  registration row says `permissive-dev`/unverified, the turn's sandbox view
  answers `backend=none, verified=false`, the worker log prints the
  mode-ceiling warning) — recorded in `docs/m3-contract.md` § 7.
* **Probe wording is load-bearing.** Claude Code refuses turns shaped like
  exfiltration tests (observed verbatim: `echo PWNED >` markers, "dump the
  .env", "don't look it up another way", "sandbox self-diagnostic" framing).
  The script therefore uses the one plain pattern that was observed to be
  obeyed — "Use the Bash tool to run exactly `<command>` and report the FULL
  outcome…" — one command per turn, neutral artifact names. A refused probe
  FAILs visibly; it never silently counts as a denial.
