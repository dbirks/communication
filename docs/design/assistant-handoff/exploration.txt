### TRUST 
F · "Ask for risky": how it decides, and better copy 
There's no classifier. internal/assistant/trust.go has a fixed table: every tool name is read , navigate , draft edit or risky , and an unknown tool is refused. The model can't relabel a tool. That's predictable and testable. The cost is that every new tool needs a class, which is why the list in G has one per row. Undo really exists only for draft edits (they store an inverse). Runs, approvals and publishes say "can't be undone" in the change list, but the menu copy promises otherwise. 
 1o Same menu, honest copy 
 Ask before everything 
It explains and proposes. You confirm every change, including draft edits. 
 ✓ Ask for risky actions default 
Reads, navigates and edits drafts on its own. Asks before creating projects, starting runs, approving or publishing. 
 Don't ask 
Does what you ask, including runs, approvals and publishing. Every action is listed in the thread. Most can't be reversed.

 TOOL CLASS ANSWERS NOTES

 docs.search read "How do I add a project?" Answers from the app's own docs, not from guesses. Index a curated how-to set, not the whole spec

 repo.check read Given a URL: does a credential reach it, default branch, push rights. Egress to GitHub API only

 profile.list / schedule.list read Agents and scheduled runs.
