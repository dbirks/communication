× WHAT'S WRONG WITH 1a
  1. Two navigations: the sidebar tree, then a second 160px section rail. The handoff never designed this page; it predates the sidebar.
  2. Content is capped at 1024px and split into 160 + 512 + 320 columns, so the right column wraps everything.
  3. Workspaces (dashed) prints worker ids, volume ids, refs and base→head commits. It's operator data on a user page.
  4. Run chips show raw enum words (WAITING_HUMAN, CANCELLED) and Recent runs repeats what Needs attention already says.
  5. Conversation rows show raw ISO timestamps and “controller:” jargon. The page calls them Conversations, the sidebar calls them Threads.
  6. Add-repository and add-member forms sit on the overview. Both header buttons are secondary, so there is no primary action.
→ WHAT 1b / 1c CHANGE
  1. One navigation. 1b uses tabs in the page header. 1c puts the sections under the open project in the sidebar tree, so the sidebar is the only menu.
  2. Full content width. Things that need you sit at the top with the actions inline (Approve, Retry from test).
  3. Only active runs get a row; finished ones collapse into one count line.
  4. Each repo shows its workflow and issue counts and opens the repo page. Workflows assigned to the project get an Edit link.
  5. Members, workspaces and activity move to Settings and the run pages. "Conversations" becomes "Threads" everywhere.
