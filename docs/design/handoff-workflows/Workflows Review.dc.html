→ NOTES
  1. Library workflows are templates. They run only where a repo uses them, pinned to a revision. So the workflow page has no Start run and no trigger editing. Its “Used in” tab (2a) lists each repo, the pinned revision (with “Update to r2” when behind), its triggers as read-only sentences, and the last run.
  2. Triggers are edited on the repo page (2e), in a “Starts when” box under each workflow the repo uses. The project page's Workflows tab shows the same rows across all of the project's repos.
  3. The dialog (2c) opens with the workflow and repo already set, so it only asks when and with which labels or schedule.
  4. Icons: Lucide (github, clock, play) at 14px, stroke 2, currentColor. That's a new dependency (lucide-react), so flag it per AGENTS.md.
  5. Every YAML view should use block style: lists as “- item”, maps nested under their key, no inline { } or [ ].

× WHAT'S WRONG WITH 1f
  1. The canvas picks left-to-right or top-to-bottom per graph (chooseCanvasOrientation), and a linear 4-step template gets left-to-right. Handles sit on the left and right sides, so after you drag a step below another, the line leaves the side and wraps around (circled).
  2. The “+” at the end sits under the last node's bottom edge. In a left-to-right graph, that's off the line.
  3. Deleting a step only works with Backspace/Delete, and nothing on screen says so.
  4. The palette uses rounded-md, uppercase 11px headings and two-line cards. Those are Tailwind defaults, not the ds tokens (3px radius, mono 10px labels), which is why it looks off next to the sidebar (dashed).
  5. The page height is calc(100vh − 91px) for a top bar that no longer exists, so 91px at the bottom is left empty.
  6. The header packs 2 chips, 4 tabs, 6 buttons and a truncated publish reason into one row. Runs and Assigned link back to the workflow page.
→ WHAT 1g CHANGES
  1. The layout is always top-to-bottom: handles are Top and Bottom, and routeEdge prefers vertical, even for steps next to each other in a loop. A dragged step still connects bottom to top.
  2. Every “+” sits on its line, centered, including the end stub under the last step. Hovering one turns it royal and shows “insert step”.
  3. The selected step shows a small menu next to it (Duplicate, Delete ⌫), and the inspector header has a Delete button.
  4. The palette uses the ds rows: mono labels, the kind glyphs (◆ ◇ ▸ ⊙ ↻), 32px rows, and a tip about click vs. drag.
  5. The header keeps Canvas/YAML, undo/redo, Validate, Save and Publish. The publish reason moves to a status bar along the bottom. The canvas fills the page height.
